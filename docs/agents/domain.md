# Domain docs

FIMBox uses a single-context domain documentation layout.

Before exploring, read [project context](../../.ai/CONTEXT.md) for project
structure and file purposes. It is not a glossary; preserve it and keep it
current for structural changes.
Read ../../GLOSSARY.md and relevant ADRs in ../adr/ when they exist.
If a glossary or ADR directory is absent, proceed silently; do not create
placeholder domain documents. The domain-modeling skill creates them lazily
when terminology or decisions are resolved.

Use glossary vocabulary in issues, proposals, hypotheses, and tests. Note
real terminology gaps for domain-modeling; avoid inventing competing synonyms.
Surface conflicts with existing ADRs explicitly rather than overriding them.
