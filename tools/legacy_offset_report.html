2. Why the input cells are the reference

For each of the four relevant non-lake HydroIDs, interpolate stage at 7.0 m³/s, round to four decimals and store as float32. A cell floods only when:

catchment == HydroID
AND original REM >= 0
AND original REM < interpolated stage
HydroID / input colorStage (m)

The REM is relative elevation, not a basemap or aerial image. Catchment colors identify HydroIDs, not flood depths. REM display range is clipped to 0–2 m for contrast; calculations and inspection retain the original values.

3. Where the legacy placement went wrong

In the pinned NOAA branch mosaic, a partition converts pixel coordinates to map coordinates and back. Floating-point error leaves the destination window just below an integer:

Intended mosaic row:  3906
Recovered float row:  3905.999999999977
Read starts at row:   3906
Write lands at row:   3905

Source flood pixel:   row 4281
Legacy flood pixel:   row 4280
Difference:           1 row north = 10 m

The mosaic shifts the pixels before the final crop. The Parquet migration changes index serialization, not this placement. Integer-window handling is the correction point; a universal output shift is not justified.
